# Журнал нарушений инкассации: что создать в Конфигураторе

Делать сначала на **копии базы**. Перед началом: Конфигуратор → Конфигурация → Сохранить конфигурацию в файл (`.cf`) - это резервная копия.

## 1. Перечисление «СтатусыНарушенийИнкассации»
Дерево метаданных → Перечисления → Добавить.
- Имя: `СтатусыНарушенийИнкассации`, синоним «Статусы нарушений инкассации».
- Значения (имя → синоним):
  - `Новое` → «Новое»
  - `ВРаботе` → «В работе»
  - `Объяснено` → «Объяснено»
  - `Закрыто` → «Закрыто»
  - `УстраненоАвтоматически` → «Устранено автоматически»

## 2. Регистр сведений «НарушенияИнкассации»
Дерево метаданных → Регистры сведений → Добавить.
- Имя: `НарушенияИнкассации`, синоним «Нарушения инкассации».
- Вкладка «Данные»: периодичность **«Непериодический»**, режим записи **«Независимый»**.
- Измерения (снимите флаги «Запрет незаполненных значений» и «Ведущее»):

| Имя | Тип |
|---|---|
| `Касса` | `СправочникСсылка.Кассы` |
| `ВидНарушения` | Строка, длина 50 |
| `ДатаНарушения` | Дата, состав «Дата» |
| `КлючДокумента` | Строка, длина 100 (может быть пустой) |

- Ресурсы: `СуммаРКО`, `СуммаВБанке`, `Разница`, `Остаток` - все Число, длина 15, точность 2.
- Реквизиты:

| Имя | Тип |
|---|---|
| `Описание` | Строка, неограниченная длина |
| `Статус` | `ПеречислениеСсылка.СтатусыНарушенийИнкассации` |
| `ДатаФиксации` | Дата, состав «Дата и время» |
| `ДатаЗакрытия` | Дата, состав «Дата и время» |
| `КемЗафиксировано` | Строка, длина 100 |
| `КемИзменено` | Строка, длина 100 |
| `Ответственный` | Строка, длина 100 |
| `Комментарий` | Строка, неограниченная длина |

- Формы: на вкладке «Формы» создайте **форму списка** (кнопка с лупой → Конструктор). В списке можно править «Статус», «Ответственный», «Комментарий».

## 3. Доступ и меню
- Роли: добавьте роли, которые будут работать с журналом, права на регистр: просмотр, чтение, добавление, изменение, редактирование (проверка - вход под этим пользователем).
- Чтобы открывать журнал из интерфейса: добавьте регистр в подсистему (например «Казначейство») или откройте через Сервис → Параметры → «Отображать команду Все функции».

## 4. Обновить базу и проверить
1. Конфигурация → Обновить конфигурацию базы данных (F7), согласиться на обновление.
2. Запустить 1С (в режиме Предприятия), открыть новую обработку `КонтрольИнкассации.epf`.
3. Вкладка «Отчёт»: поставить флажок **«Записывать в журнал нарушений»**, нажать «Сформировать».
4. В окне сообщений: «Журнал нарушений: новых N, обновлено M, устранено автоматически K». Если пишет, что журнал не создан, проверьте имена `НарушенияИнкассации` и `СтатусыНарушенийИнкассации`.
5. Откройте список регистра «Нарушения инкассации»: там записи по красным ошибкам. Поставьте одной записи статус «В работе» и комментарий, снова нажмите «Сформировать»: статус и комментарий должны остаться.
6. Если нарушение пропало (деньги пришли в банк, остаток упал), при следующей проверке за тот же период оно получит статус «Устранено автоматически» и дату закрытия.

## 5. Отчёт для истории (по желанию)
Отчёты → Добавить → «Нарушения инкассации», схема компоновки данных (Конструктор). Запрос:

```
ВЫБРАТЬ
	Н.Касса КАК Касса,
	Н.Касса.Владелец КАК Организация,
	Н.ВидНарушения КАК Вид,
	Н.ДатаНарушения КАК Дата,
	НАЧАЛОПЕРИОДА(Н.ДатаНарушения, МЕСЯЦ) КАК Месяц,
	Н.Статус КАК Статус,
	Н.СуммаРКО КАК СуммаРКО,
	Н.СуммаВБанке КАК СуммаВБанке,
	Н.Разница КАК Разница,
	Н.Остаток КАК Остаток,
	Н.Описание КАК Описание,
	Н.Ответственный КАК Ответственный,
	Н.Комментарий КАК Комментарий,
	Н.ДатаФиксации КАК ДатаФиксации,
	Н.ДатаЗакрытия КАК ДатаЗакрытия,
	1 КАК Количество
ИЗ
	РегистрСведений.НарушенияИнкассации КАК Н
```

Ресурс: `Количество` (сумма), `Разница` (сумма). Варианты отчёта (вкладка «Настройки»):
- **Журнал**: детальные записи, поля Дата, Касса, Вид, Статус, Описание, Ответственный; отбор по периоду.
- **Магазины × виды**: строки - Касса, колонки - Вид, ресурс - Количество.
- **Динамика по месяцам**: строки - Месяц, колонки - Вид, ресурс - Количество.
- **Рейтинг**: группировка по Касса, порядок по Количество убывание.
- **Не закрыты**: отбор Статус «в списке» Новое, В работе; поле ДатаФиксации.

## 6. Что дальше (отдельный этап)
- Регламентное задание «раз в день сама проверяет»: для этого логику проверки нужно перенести из формы обработки в общий модуль конфигурации. Это следующий шаг, после того как журнал заработает.
- Оповещения директорам (почта, МАХ) поверх журнала.
