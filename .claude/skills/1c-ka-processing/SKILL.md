# Обработки и расширения 1С КА в проекте

## Как работаем
- Платформы 1С в окружении нет: `.cfe`/`.epf` не собрать и BSL не запустить. Пишем BSL-исходники, сам алгоритм
  проверяем эталоном на Python (`rpa1c/razdelka.py`, тесты `tests/test_razdelka.py`, запуск `pytest`).
  При правке алгоритма меняем ОБА места (Python и BSL) и прогоняем тесты.
- Исходники: `1c_extension/` (расширение — основной вариант), `1c_epf/` (внешняя обработка, без кнопки в форме и без вопроса при записи).
  Архив для передачи пользователю собираем в `dist/` и отправляем файлом (репозиторий приватный, прямой ссылки нет).
- Имена метаданных НЕ угадывать: брать из выгрузки конфигурации (`Documents/питРазделка.xml`, форма, модули)
  или просить у пользователя. Пользователь не владеет Конфигуратором — давать пошаговые инструкции с названиями
  кнопок и закладок, просить скриншот при ошибке.

## Проверенные факты базы (КА 2.5.22, копия)
- Документ `питРазделка` в ОСНОВНОЙ конфигурации (на поддержке). Шапка: Подразделение (СправочникСсылка.СтруктураПредприятия),
  Номенклатура, Количество. ТЧ `Товары`: Номенклатура, КоличествоНорма, Количество (ед. хранения, факт),
  КоличествоУпаковок (видимая колонка), ПроцентВыхода (7,3), ПроцентСебестоимости (5,2). Отдельная ТЧ `ПобочныеИзделия`.
  «ОТХОДЫ» лежат в `Товары`. Реквизит `ТипЦен` (строка) на форме не используется.
- Форма `ФормаДокумента`: таблица `Товары`, панель `ТоварыКоманднаяПанель`, кнопка `ТоварыПодборТовары`.
  Ручная правка `ПроцентВыхода` вызывает клиентский пересчёт факта; серверная запись доли его НЕ вызывает.
  Серверный пересчёт факта при записи отсутствует. Норму (`КоличествоНорма`) не пересчитываем — остаётся из рецептуры.
  Проверку дублей строк делает документ (`ПроверитьТоварыНаДубли`), расчёт её не дублирует.
- РС `ЦеныНоменклатуры`: период — секунда; измерения Номенклатура, Характеристика, ВидЦены (СправочникСсылка.ВидыЦен);
  ресурсы Цена, Упаковка, Валюта. В разделке только кг. Розничные виды цен: «Розничная <магазин>».

## Правила расширения
- Одно расширение не заимствует объекты другого; объект сначала «Добавить в расширение» из основной конфигурации,
  только потом его можно использовать как тип реквизита/константы.
- Обращения вида `Константы.Имя` и `РегистрыСведений.Имя` синтаксический контроль НЕ проверяет — убедиться, что
  объекты созданы и входят в состав подсистемы настроек.
- Константы расширения не видны в меню: заводим подсистему `РазделкаНастройки` («Включать в командный интерфейс»)
  и включаем в состав константы и регистр.
- Меняем в документе только колонки долей; факт, номенклатуру, порядок строк, норму не трогать.
- Вопрос «Пересчитать доли?» при записи — клиентский `ПередЗаписью` с флагом `ДолиОбработаны` в `ПараметрыЗаписи`
  (иначе зациклится); «Нет» — запись как есть, крестик — отмена.

## Алгоритм долей (источник — ТЗ пользователя)
1 строка → 1/1. Доля выхода = факт/Σфакта, 3 знака, остаток 1,000−Σ → строке с макс. фактом (при равенстве первой).
Вес = факт×цена (отходы — 0); доля с/с = вес/Σвес, 2 знака, остаток → строке с макс. весом.
Настройка «минимальная доля» 0 или 0,01 (вычитается у строки с макс. весом). Округление half-up (`Окр(...,N,1)`).
Цена: вид цен подразделения (РС `РазделкаВидЦенПодразделения` → константа `РазделкаВидЦенДляРасчетаДолей`),
иначе самая частая из последних цен по розничным видам (`ВидЦены.Наименование ПОДОБНО "%озничн%"`), иначе 0.
Эталон-пример: КТЦБ-004740 → 0,400/0,375/0,225 и 0,43/0,53/0,04.

## Ловушки Конфигуратора (проверено на этой базе)
- Расширение применяется кнопкой «Конфигурация → Конфигурация базы данных → Обновить конфигурацию базы данных» при активной панели
  расширения; пока у панели расширения звёздочка (`*`), изменения не сохранены. После — полный перезапуск 1С.
- Префикс имени расширения по умолчанию `Расш1_`: роль `Расш1_ОсновнаяРоль` конфликтует с другими расширениями
  («Уже существует объект с именем Роль…») → переименовать роль и префикс (`РазделкаДоли_`).
- Модуль объекта заимствованного документа расширяется только при снятом флаге «Безопасный режим» у расширения;
  перехват — `&После("ПередЗаписью")`, реквизиты основного объекта — через `ЭтотОбъект.`.
- Действие команды в форме расширения: выбрать/вписать готовую процедуру (стрелка ▼ или имя вручную), не создавать
  через лупу — Конфигуратор делает пустую заготовку `Расш1_…Перед/После`, и кнопка молча ничего не делает.
- Клиентскому `ПередЗаписью` формы нужна привязка в свойствах формы → «События».
- Заимствовать нужно именно `ВидыЦен` (не `ВидыЦенПоставщиков`); константе/ресурсу тип `СправочникСсылка.ВидыЦен`.
- Цены берутся строго на дату документа (`СрезПоследних(&Дата, …)`); отходы распознаются по началу наименования
  («Свинина ОТХОДЫ охл кг МЦ»); отбор розничных видов цен — во внешнем запросе, не в условии виртуальной таблицы.
- Кнопка показывает уведомление с суммами и список позиций без цены — так видно, что расчёт реально выполнен.
- Проведение блокируется, если итого доля себестоимости ≠ 1 (только операция РецептураРазделка); запись — предупреждение.
- Подтверждённый результат: КТЦБ-005666 (18 строк свинины) — сумма долей выхода 1,000, с/с 1,00, факт и норма не меняются.

## Открытое
- Заполнить РС «Подразделение → вид цен» (например, МЦ Каспийская Сочи → «Сочи 2 кат. Каспийская розничная»).
- Решить: минимальная доля 0 или 0,01 (сейчас 0, как в Excel).
- Сверка с Excel за июль–октябрь на 10–20 документах — расхождения добавлять в `tests/test_razdelka.py`.
- Характеристика — измерение регистра цен; при разных ценах по характеристикам срез вернёт несколько строк (сейчас берётся последняя).
