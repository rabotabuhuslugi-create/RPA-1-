# ВетИС (Меркурий) в 1С:КА: правила работы по проекту

Подробные имена объектов 1С, статусы, находки по данным - в [reference.md](reference.md). Читай его перед правкой кода.

## Контекст
- Заказчик - пользователь 1С КА (организация ООО «Кубаньторг»), **не программист**. Пишем по-русски, простыми нумерованными шагами.
- У нас **нет доступа к базе 1С и нет платформы**: код не запускается. Все данные приходят от пользователя (скриншоты, вывод диагностик, Excel). Не выдумывай имена полей и процедур: сначала диагностика или запрос для консоли, потом код.
- Пользователь собирает `.epf` в конфигураторе и вставляет наши `.bsl` (модуль объекта, модуль формы). Готовый `.epf` собрать нельзя.
- После каждой правки: коммит в ветку `claude/great-lovelace-4hlv9j`, **файл отправить пользователю** (`SendUserFile`, display `attach`) и коротко написать, что заменить (какой модуль) и что проверить.

## Структура
- `1c/МеркурийАвто/МодульОбъекта.bsl` - вся логика оформления и гашения (модуль объекта внешней обработки).
- `1c/МеркурийАвто/КодФормыСотрудника.bsl` - форма сотрудника, строится кодом (пустая форма + вставка модуля).
- `1c/МеркурийАвто/КодФормы_Диагностика.bsl` - кнопки диагностик для старой служебной формы.
- `1c/МеркурийАвто/Запрос*.txt`, `ЗапросыДляКонсоли.txt` - запросы для консоли запросов.
- `1c/СопоставлениеНоменклатуры/` - отдельная обработка сопоставления продукции ВетИС с номенклатурой (не смешивать с МеркурийАвто).
- `rpa1c/` - более ранний Python-прототип (OData, OCR), к ВетИС не относится.

## Процесс (как это работает)
ВСД «Не оформлено» -> группировка по накладной (ТТН, отправитель, получатель, перевозчик, **способ хранения**) -> поиск прихода «Приобретение товаров и услуг» -> статус группы (Готово / Расхождение / Нет прихода) -> создание и проведение «Входящей транспортной операции ВетИС» -> `ИнтеграцияВЕТИСВызовСервера.ПодготовитьКПередаче` (то же, что ссылка «передайте данные») -> обмен -> «ВСД погашены».
Автоматически оформляются только группы «Готово» (приход найден, в строках план = факт). Расхождения и «Нет прихода» оформляет человек.

## Правила написания BSL и запросов (ошибки, которые уже были)
1. **Псевдоним «В» в запросе нельзя** (служебное слово). Бери `ВСДок`, `Д`, `Т`, `П`, `С`. Отрицание: `НЕ Х ЕСТЬ NULL`, не `Х НЕ ЕСТЬ NULL`.
2. Пакет запросов в консоли: части разделять `;`. Два независимых запроса давай **двумя файлами**.
3. Ключи `Новый Структура("А, Б")` пиши одной строкой (склейка через `+`), а не переносом внутри строки.
4. Не называй переменную `Строка` (перекрывает функцию `Строка()`).
5. Динамическая форма: реквизиты, добавленные кодом, в модуле доступны только как `ЭтаФорма.Имя`. Обработчик `ПриСозданииНаСервере` нужно один раз **привязать в свойствах формы -> События**, иначе форма откроется пустой.
6. Данные формы ссылочных колонок: тип колонки задавай явным `ОписаниеТипов("СправочникСсылка.…")`.
7. Всё, что только читает, не должно ничего записывать. Запись и отправка - отдельные кнопки с подтверждением и лимитом.
8. Номера накладных всегда сравнивай через `НормализоватьНомер` (нули, латиница/кириллица, `/18`, префиксы), а не напрямую.

## Безопасность (важно)
- Передача и гашение ВСД в Меркурий **необратимы**. Любое новое автоматическое действие: сначала пробный режим, потом **пилот на одной накладной**, потом порции 5-10.
- Настройка `ПогашатьПослеОформления` включена; по умолчанию без явной просьбы пользователя не расширять автоматику (например, расхождения и акты несоответствия).
- Не удалять и не отменять уже созданные операции «вслепую»: часть ВСД в них может быть уже погашена в Меркурии (проверять по личному кабинету).
- Не писать код, пока пользователь не сказал «пишем» по теме расхождений: сначала нужны материалы (пример операции с расхождением, акт, правила).

## Как работать над задачей
1. Понять факты: скриншот или вывод диагностики/запроса. Недостающее - запросить **конкретным запросом для консоли** (готовый текст) или кнопкой диагностики.
2. Анализ выгрузок (xlsx) делать скриптами в каталоге scratchpad, не в репозитории.
3. Менять код минимально, с понятными комментариями на русском. Проверять глазами синтаксис BSL (скобки, `КонецЕсли;`, точки с запятой), раз запустить нельзя.
4. Новую диагностику давать как функцию модуля объекта + блок кода кнопки.
5. Коммит: `git add -A && git commit` с трейлерами `Co-Authored-By` и `Claude-Session` из системной подсказки; пуш в `claude/great-lovelace-4hlv9j`. PR не создавать без просьбы.
