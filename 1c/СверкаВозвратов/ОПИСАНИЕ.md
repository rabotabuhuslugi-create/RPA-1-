# Сверка возвратов поставщику и корректировок приобретения
Внешняя обработка для 1С:Комплексная автоматизация 2.5. Файл: `SverkaVozvratov.epf` (собирается из папки `dump` скриптом `build_epf.bat`).

## 1. Для чего
Директор магазина оформляет **возврат товаров поставщику**. Поставщик через ЭДО присылает **корректировки приобретения** (К1, К2, К3…). Бухгалтеру нужно:
1. убедиться, что каждая позиция возврата закрыта корректировкой поставщика;
2. провести корректировки в правильном порядке (К1 → К2 → К3, с перезаполнением «Товаров» и счетами-фактурами);
3. удалить возврат, когда он полностью закрыт.

Обработка делает это автоматически и безопасно: сначала показывает, что будет сделано (пробный режим), потом выполняет.

## 2. Как пользоваться (два шага)
1. **«Подобрать»**. Укажите контрагента (поставщика) и период возвратов («Период с» — «Возвраты по»). Корректировки ищутся автоматически за 3 месяца после каждого возврата. Организация необязательна.
   «Подобрать» выполняется тремя видимыми шагами (в строке состояния): чтение из базы → подбор пар → формирование списка. Обработка покажет возвраты со статусами и сама отметит галочкой то, что имеет смысл обрабатывать.
2. **«Выполнить»**. Снимите галочки с лишнего и нажмите кнопку. Сначала работает **пробный режим** (флажок включён по умолчанию): в базе ничего не меняется, внизу в «Журнале» видно, что будет сделано. Для реального запуска снимите флажок «Пробный режим».

После реального запуска таблицы не обновляются сами: нажмите «Подобрать» заново.

### Что на экране
Сверху — параметры (организация, контрагент, период возвратов), кнопки **«Подобрать»**, **«Выполнить»** и **«Настройки»**, флажок «Пробный режим». Кнопка «Настройки» открывает окно настроек (как в отчётах) с полями: срок корректировки в месяцах, допуск «раньше возврата» в днях, дату проведения, лимит возвратов за запуск, допуск по количеству, максимум возвратов в комбинации, максимальное время точного подбора, проведение счетов-фактур.

Под ними строка-итог: сколько возвратов можно удалить, сколько ждут корректировок, сколько без совпадений, сколько отмечено.

Ниже три вкладки:
| Вкладка | Что показывает |
|---|---|
| **Возвраты и корректировки** | Дерево: верхний уровень — возвраты (галочка «Обработать», статус, дата), внутри — позиции возврата с найденной корректировкой и её количеством. Незакрытые возвраты развёрнуты, закрытые свёрнуты. Двойной щелчок по возврату открывает возврат, по позиции — корректировку. |
| **Корректировки: даты проведения** | Все найденные корректировки: статус, дата, «Проведена», **«Дата проведения»** (для непроведённых можно менять), поступление-основание, связанные возвраты. |
| **Журнал выполнения** | Результат нажатия «Выполнить»: по возвратам и по каждой корректировке (✔ выполнено, ✖ ошибка, • информация). Двойной щелчок открывает корректировку. |

## 3. Как работает подбор
**Что читается** (обработка ничего не пишет на этом шаге):
- Возвраты: `ВозвратТоваровПоставщику`, **только проведённые**, не помеченные на удаление, за период, выбранного контрагента.
- Корректировки: `КорректировкаПриобретения` за окно «с начала периода минус допуск раньше возврата — до конца периода плюс срок корректировки» по дате документа поставщика, **проведены или нет** (вкладка «Расхождения» заполняется из ЭДО сразу), не помеченные на удаление. Берутся только строки «Расхождения» с вариантом отражения **«Уменьшить закупку, уменьшить складские остатки»**; количество берётся по модулю.

**Как сопоставляются строки.**
1. Ключ: **номенклатура + склад + поставщик**.
2. Допустимость по срокам и поступлению (все условия обязательны):
   - корректировка поставщика приходит **не позже 3 месяцев после возврата** (срок меняется в окне «Настройки»). Возврат могут провести уже **после прихода корректировки**, поэтому корректировка может быть **раньше возврата не более чем на 30 дней** (тоже настройка). Если в возврате явно указано то же поступление, что в основании корректировки, нижняя граница не применяется. Берётся дата документа поставщика (входящая дата корректировки), а если её нет — дата корректировки; перенос даты проведения у нас на сверку не влияет;
   - поступление, по которому пришла корректировка, **раньше возврата**;
   - если в возврате указано поступление — оно должно совпасть с основанием корректировки.
3. Количество: либо одна строка возврата с тем же количеством (допуск 0,01), либо **комбинация нескольких строк возвратов**, дающая количество строки корректировки (до 6 строк в комбинации).
4. Одна строка возврата используется только один раз.
5. **Точный подбор (максимум закрытых возвратов).** Корректировки делятся на независимые группы (общие возможные строки возврата). В каждой группе перебираются варианты, какие корректировки закрыть **целиком** и какими строками возврата; выбирается вариант, закрывающий **больше всего строк возврата**, при равенстве — больше корректировок. Для каждой строки корректировки рассматриваются: одна строка возврата с тем же количеством и комбинации из нескольких строк. Подбор стартует с быстрого жадного решения и затем улучшает его перебором; перебор ограничен **по времени** (настройка «Макс. время точного подбора», по умолчанию 5 сек на весь подбор, делится между группами): по истечении времени, а также если полторы секунды нет улучшений, берётся лучшее из найденного, не хуже жадного. Есть и жёсткий предел на весь подбор (не меньше 30 секунд): после него комбинации не ищутся, остаются только одиночные совпадения. Обработка не зависает на больших объёмах. После этого для оставшихся корректировок добираются частичные совпадения (они нужны для справки и для ожидания недостающих корректировок).

**Статусы возврата:**
| Статус | Условие |
|---|---|
| ✔ Можно удалить | все позиции возврата нашли пару **и** каждая закрывающая корректировка закрыта полностью (все её позиции нашли возврат) |
| ⚠ Корректировка закрыта не полностью | позиции возврата найдены, но связанная корректировка содержит позиции без возврата |
| ⚠ Частично (N из M) | часть позиций возврата не нашла корректировку |
| ✖ Нет совпадений | ни одна позиция не нашла пару |

## 4. Что делает «Выполнить»
Для каждого отмеченного возврата (не больше «лимита возвратов за запуск», по умолчанию **1**):

**Возврат закрыт полностью (✔ Можно удалить):**
1. Возврат снимается с проведения и помечается на удаление (сначала возврат, потом корректировки — иначе остатки спишутся дважды).
2. Проводятся его корректировки, ещё не проведённые (подробнее в разделе 5).
3. Если корректировки провести не удалось — возврат **восстанавливается** (снимается пометка и он снова проводится). В результате будет написано, сколько корректировок уже проведено.

**Возврату не хватает корректировок (⚠ Частично):**
1. Проводятся только найденные корректировки, у которых **все** позиции сопоставлены с возвратами (чтобы не затронуть позиции без возврата).
2. Возврат **не помечается** на удаление и остаётся ждать недостающие корректировки. Когда придёт недостающая, повторите «Подобрать» и «Выполнить»: уже проведённые корректировки учитываются в сверке.

**Пробный режим:** то же самое, но без записи в базу: возврат не меняется, корректировки не проводятся, журнал показывает даты, перезаполнение и результат проверки заполнения.

## 5. Как проводятся корректировки (цепочки)
**Цепочка** — все не удалённые корректировки **одного поступления** (основания) по порядку даты и времени.
Для каждой корректировки по порядку:
1. **Дата проведения.** Берётся из колонки «Дата проведения» (по умолчанию — дата запуска обработки; можно изменить в строке). Меняется только день, **время суток исходной даты сохраняется**. Если после переноса порядок цепочки нарушается, корректировка ставится на секунду позже предыдущей. Дата раньше предыдущей корректировки цепочки — ошибка.
2. **Предыдущие корректировки цепочки.** Если раньше в цепочке есть непроведённые корректировки, которые вы не выбирали:
   - если они **сопоставились с возвратами** (статус «все позиции с возвратом»), они проводятся тоже, в порядке цепочки (в журнале: «добавлена как предыдущая в цепочке»);
   - если какая-то из них **не сопоставилась** (или сопоставилась не полностью), **проведение цепочки останавливается на ней**: всё, что стоит до неё, проводится, всё после — нет. В журнале будет сообщение с номером этой корректировки; её нужно провести вручную или дождаться недостающих документов.
3. **Перезаполнение «Товаров».** Если раньше в цепочке есть проведённая корректировка, вкладка «Товары (после корректировки)» перезаполняется по состоянию после неё — как команда формы «Заполнить корректируемые данные» (`Документы.КорректировкаПриобретения.ЗаполнитьТоварыПоИсходнымДанным`). Для первой корректировки цепочки перезаполнение не нужно.
4. **Проведение.** Корректировка проводится. Всё (дата, заполнение, проведение, счёт-фактура) выполняется **в одной транзакции** на корректировку.
5. **Счёт-фактура.** Связанная счёт-фактура ищется по документам-основаниям. Если она не проведена — «Получен» (дата документа) приводится к дате корректировки, «Запись в книге продаж» — ко дню корректировки (от неё зависит налоговый период), и счёт-фактура проводится. Если уже проведена — не меняется, но в журнале будет предупреждение, если её даты отличаются от даты корректировки. Если не найдена — пишется в журнал. Дата составления (из документа поставщика) не меняется.
6. **Ошибка** останавливает **только эту цепочку**: остальные продолжаются. Сообщение — в журнале.

## 6. Защита и ограничения
- **Пробный режим** включён по умолчанию, **лимит — 1 возврат за запуск**. Увеличивайте лимит только после успешного пилота.
- Любое изменение в базе — только по кнопке «Выполнить» и после подтверждения.
- Возврат восстанавливается, если его корректировки не провелись.
- Действия необратимы автоматически: распроведение возврата, проведение корректировок и счетов-фактур откатывайте вручную.

**Что следует знать и проверить:**
1. **Остатки при частичном возврате.** Возврат остаётся проведённым, а найденные корректировки проводятся: на время ожидания остатки по этим позициям списываются дважды. Проведение может не пройти из-за контроля остатков — тогда ошибка будет в журнале.
2. **Добавленные корректировки.** Предыдущие непроведённые корректировки цепочки проводятся, только если они сопоставились с возвратами (в том числе с другим возвратом, не отмеченным сейчас). Проверьте их в пробном режиме до реального запуска.
3. **Корректировки других вариантов.** В сверке участвуют только строки «Уменьшить закупку, уменьшить складские остатки». Если в корректировке есть строки с другим вариантом отражения, они не проверяются, но проведутся вместе с корректировкой.
4. **Налоговый период.** Дата корректировки и счёта-фактуры переносится на дату проведения (по умолчанию дата запуска). Убедитесь, что это нужный период.
5. **Проверка после перезаполнения.** «Товары» перезаполняются в коде так же, как на форме; полностью проверить результат можно только реальным проведением.
6. **Проведённая ранее счёт-фактура** с другой датой не перепроводится.

## 7. Рекомендуемый порядок запуска (пилот)
1. Подобрать → Выполнить в **пробном режиме**, изучить журнал.
2. Откройте двойным щелчком несколько корректировок, включая «добавленные».
3. Отметьте один простой возврат (с одной корректировкой), снимите пробный режим, лимит оставьте 1 → «Выполнить».
4. Проверьте возврат (помечен на удаление), корректировку (проведена, дата), счёт-фактуру (проведена, дата), остатки.
5. Только потом увеличивайте лимит.

## 8. Техническая информация

- Исходники: `1c/СверкаВозвратов/dump/` (модуль объекта — запросы, сверка, проведение цепочек; модуль формы — интерфейс и действия).
- Сборка: `build_epf.bat` (запускает `build_epf.ps1`) на копии базы.

## Печать
Кнопка «Печать» собирает табличный документ (ландшафт): шапка (организация, поставщик, период, режим, итог) и три раздела — «Возвраты и корректировки» (с позициями и цветом по статусу), «Корректировки: даты проведения», «Журнал выполнения». Каждый раздел с новой страницы. Показывается в предпросмотре, откуда можно напечатать.

## Печать и сортировка
Правая кнопка мыши по таблице и «Еще» над таблицей: «Сортировать по возрастанию / по убыванию» (по колонке с курсором; в дереве сортируются и возвраты, и позиции внутри) и «Печать» (все три вкладки одним документом).

## Проверка «Товаров» перед перезаполнением
Для непроведённой корректировки, следующей за проведённой, обработка сначала сравнивает её «Товары» с тем, что дало бы «Заполнить корректируемые данные» (по номенклатуре и характеристике). Совпало — документ не перезаполняется (правки сохраняются), отличие — перезаполняется, а в журнале видно, что отличалось.

## Вкладка «Цепочки корректировок»
Для каждого поступления, к которому относится сопоставленная корректировка, обработка берёт все его корректировки (не помеченные на удаление) по порядку даты и последовательно считает ожидаемые «Товары»: количества поступления, изменённые «Расхождениями» К1, затем К2, затем К3 и т. д. (расхождение со знаком: −1 уменьшает, +1 увеличивает; применяется ко всем последующим). Фактические «Товары» каждой корректировки сравниваются с ожидаемыми:
- ✔ Заполнена верно (зелёный) — перезаполнять не нужно;
- ✖ Нужно перезаполнить (красный) — непроведённая, «Товары» расходятся; в колонке «Что не так» видно, какие позиции и сколько в документе / должно быть;
- ✖ Проведена, «Товары» расходятся — проведённый документ с расхождением (проверьте вручную);
- — нет данных — основание не «Приобретение товаров и услуг».
Тот же результат виден в колонке «Заполнение» на вкладке «Корректировки» и в печатной форме. Проверка только читает базу.

## Перезаполнить «Товары» последовательно
Ссылка «Перезаполнить Товары последовательно» над таблицами (вкладки «Возвраты и корректировки» и «Журнал выполнения»): по порядку цепочек берёт непроведённые корректировки со статусом «перезаполнить» (на вкладке журнала — только выделенные строки, если они выделены), выполняет «Заполнить корректируемые данные» и приводит количества строк (суммы пропорционально) к ожидаемым: поступление плюс расхождения всех корректировок цепочки до этой включительно. Не получилось привести (нет строки, несколько строк одной номенклатуры) — документ не записывается, причина в журнале. Документы только записываются, не проводятся; в пробном режиме не записываются. Проведённые не меняются.

## Вкладка «Магазины»
Магазин = склад возврата. Вкладка показывает по каждому магазину: сколько возвратов, из них можно удалять (100%), к перезаполнению, ждут корректировок, без совпадений, и сколько корректировок нужно перезаполнить. Отметьте один или несколько магазинов — дерево покажет только их возвраты; «Выполнить» обрабатывает только показанные отмеченные возвраты, а «Перезаполнить Товары последовательно» — только корректировки этих магазинов. Ссылка «Показать все магазины» снимает отметки.

## Выбор корректировок для перезаполнения
В таблице цепочек первая колонка «Перезаполнить» — флажки. По умолчанию отмечены непроведённые корректировки со статусом «перезаполнить». Ссылки «Отметить все красные» и «Снять отметки» над таблицей; кнопка «Перезаполнить Товары последовательно» обрабатывает только отмеченные (плюс отбор по магазинам).
