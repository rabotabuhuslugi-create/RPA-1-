# Сверка возвратов поставщику и корректировок приобретения (1С:КА 2.5)

Внешняя обработка. Работа в два шага:

1. **«Подобрать»** — укажите контрагента и период. Обработка сопоставит возвраты и корректировки и отметит
   галочками то, что имеет смысл обрабатывать (лишние галочки можно снять).
2. **«Выполнить»** — для каждого отмеченного возврата:
   - **возврат закрыт полностью** (статус «✔ Можно удалить»): возврат снимается с проведения и помечается на
     удаление, **сопоставленные корректировки проводятся** (цепочкой по порядку даты, с перезаполнением «Товаров»,
     вместе со счёт-фактурой). Если корректировки провести не удалось — возврат восстанавливается как был;
   - **возврату не хватает корректировок** («⚠ Частично»): проводятся только найденные корректировки, у которых
     все позиции сопоставлены с возвратами; **возврат остаётся** (не помечается) и ждёт, пока придёт недостающая
     корректировка — после её появления нажмите «Подобрать» и «Выполнить» ещё раз.

Безопасность: по умолчанию включён **«Пробный режим»** (ничего не записывает, в журнале видно, что будет сделано)
и лимит **1 возврат за запуск**. Остальные настройки (срок корректировки, допуск «раньше возврата», дата проведения, лимит, допуск, счета-фактуры и др.)
открываются кнопкой «Настройки» в отдельном окне.

Результаты — на вкладке «Журнал выполнения»; двойной щелчок по строке открывает документ. Подбор максимизирует число закрытых возвратов (точный перебор по группам).

## Правила сверки и проведения (подробно)
## Что делает
1. Берёт за период **проведённые** возвраты поставщику (`ВозвратТоваровПоставщику`) выбранного контрагента
   и **все** корректировки приобретения (`КорректировкаПриобретения`, проведены или нет) — только строки
   таблицы «Расхождения» с вариантом отражения «Уменьшить закупку, уменьшить складские остатки»
   (количество берётся по модулю).
2. Сопоставляет по ключу **номенклатура + склад + поставщик** и **допустимости по срокам и поступлению** (корректировка не позже 3 месяцев после возврата и не раньше возврата более чем на 30 дней — возврат могут провести позже прихода корректировки; поступление раньше возврата)
   (если в возврате указано поступление — оно должно совпасть с основанием корректировки; иначе поступление
   корректировки не может быть позже возврата, т.е. возврат 2025 года не свяжется с корректировкой к поступлению 2026): точное количество одной строки возврата
   или подбор комбинации строк возвратов (до N, по умолчанию 6), дающей количество строки корректировки.
3. Возврат получает статус **«Можно удалить»** только если все его позиции нашли пару **и** каждая закрывающая
   его корректировка тоже закрыта полностью (все её позиции нашли возврат). Иначе «Частично» / «Нет совпадений».
4. У корректировок есть колонка **«Дата проведения»**: у проведённой — её дата (менять нельзя), у не проведённой —
   дата по умолчанию из поля «Дата проведения непроведённых корректировок» (по умолчанию = дата запуска обработки),
   её можно править по строкам или кнопкой «Применить дату ко всем непроведённым». Дата будет использована
   на этапе 2 (проведение цепочек); сейчас она ничего не записывает.
5. Показывает: список возвратов со статусами и галочками, детали по позициям (какая корректировка и количество),
   таблицу связанных корректировок. Двойной щелчок открывает документ.
6. Кнопка «Пометить выбранные на удаление»: только для статуса «Можно удалить», с подтверждением;
   проведённый возврат сначала распроводится; каждый документ — в своей транзакции, ошибки в колонке «Результат».

Обработка **ничего не пишет**, пока не нажата «Пометить выбранные на удаление».

## Как получить .epf (без программирования)
1. Скопируйте папку `1c/СверкаВозвратов` на компьютер с Windows, где установлена платформа 1С
   и есть **копия вашей базы** (форма использует документы и справочники КА, в пустой базе сборка не пройдёт).
2. Закройте Конфигуратор этой базы и дважды щёлкните `build_epf.bat` (он запускает `build_epf.ps1` на PowerShell, чтобы русский логин передавался без искажений). Ответьте на вопросы: файловая или
   серверная база, путь (или сервер и имя базы), пользователь и пароль. База при этом **не изменяется**.
3. Рядом появится `SverkaVozvratov.epf` (при ошибке пришлите `build.log`).
4. В 1С: Файл → Открыть → выберите `.epf`.

## Первый запуск (обязательно на копии базы)
1. Укажите **контрагента**, период, нажмите «Подобрать».
2. Проверьте несколько пар вручную: откройте возврат и корректировку двойным щелчком.
3. Сравните результат с внешней программой (HTML-инструментом) на тех же данных.
4. Только потом — «Пометить выбранные на удаление» на 1–2 возвратах.

## Что использовано из конфигурации (из выгрузки)
- `Документ.ВозвратТоваровПоставщику`: Контрагент, Организация, Склад, Дата, Номер, ТЧ Товары (Номенклатура, Склад, Количество).
- `Документ.КорректировкаПриобретения`: Контрагент, Организация, Склад, ДокументОснование, ТЧ Расхождения
  (Номенклатура, Склад, Количество, ВариантОтражения).
- `Перечисление.ВариантыОтраженияКорректировокПоступлений.УменьшитьЗакупкуУменьшитьСкладскиеОстатки`.

## Этап 2: проведение цепочек корректировок
Цепочка — все не удалённые корректировки **одного поступления** (`ДокументОснование`) по порядку даты и времени.

1. После пометки возвратов на удаление их непроведённые корректировки отмечаются в колонке «Провести»
   (или кнопка «Отметить корректировки выбранных возвратов»). Галочки и даты можно править вручную.
2. Кнопка «Провести цепочки корректировок». Для каждой цепочки по порядку:
   - дата проведения: берётся из колонки «Дата проведения» (только день; время суток сохраняется, при совпадении
     дня порядок цепочки поддерживается сдвигом на секунды);
   - если раньше в цепочке уже есть проведённая корректировка — как команда формы «Заполнить → Заполнить
     корректируемые данные» перезаполняется вкладка «Товары» (`Документы.КорректировкаПриобретения.ЗаполнитьТоварыПоИсходнымДанным`);
   - корректировка проводится, затем проводится связанная счёт-фактура (ищется по `СчетФактураПолученный.ДокументыОснования`,
     дата приводится к дате корректировки);
   - всё это — в одной транзакции на корректировку.
3. Непроведённые корректировки того же поступления, которые стоят в цепочке **раньше выбранных**, но сами не выбраны
   (их нет в таблице, т.к. они не связаны с возвратами), при включённом флажке «Проводить и предыдущие непроведённые
   корректировки цепочки» (по умолчанию включён) проводятся тоже, датой по умолчанию; в журнале они помечены
   «добавлена как предыдущая в цепочке». Если флажок выключен — такая цепочка не проводится, пока вы их не проведёте вручную.
4. **Ошибка останавливает только свою цепочку**, остальные продолжаются. Если раньше в цепочке стоит непроведённая
   корректировка, которая не выбрана, последующие не проводятся (порядок нельзя нарушать).
5. Безопасность: по умолчанию включён **«Пробный режим»** (ничего не записывается: показывает даты, перезаполнение,
   проверку заполнения и число найденных счетов-фактур) и **лимит 1 цепочка за запуск** — для пилота.
   Результаты — в таблице «Журнал» (двойной щелчок открывает корректировку).

**Что нужно проверить на первом пилоте** (в коде это не проверялось, платформы нет):
- проводится ли счёт-фактура сама при проведении корректировки (журнал покажет «уже проведена» или «не найдена»);
- что после перезаполнения «Товаров» корректировка проводится без ошибок.

## Печать
Кнопка «Печать» в шапке формирует один документ из трёх вкладок (возвраты с позициями, корректировки с датами проведения, журнал) и открывает предпросмотр; оттуда — печать или сохранение.

## Печать и сортировка
Правая кнопка мыши по таблице и «Еще» над таблицей: «Сортировать по возрастанию / по убыванию» (по колонке с курсором; в дереве сортируются и возвраты, и позиции внутри) и «Печать» (все три вкладки одним документом).

## Проверка «Товаров» перед перезаполнением
Для непроведённой корректировки, следующей за проведённой, обработка сначала сравнивает её «Товары» с тем, что дало бы «Заполнить корректируемые данные» (по номенклатуре и характеристике). Совпало — документ не перезаполняется (правки сохраняются), отличие — перезаполняется, а в журнале видно, что отличалось.

## Вкладка «Цепочки корректировок»
Для каждого поступления, к которому относится сопоставленная корректировка, обработка берёт все его корректировки (не помеченные на удаление) по порядку даты и последовательно считает ожидаемые «Товары»: количества поступления, изменённые «Расхождениями» К1, затем К2, затем К3 и т. д. (расхождение со знаком: −1 уменьшает, +1 увеличивает; применяется ко всем последующим). Фактические «Товары» каждой корректировки сравниваются с ожидаемыми:
- ✔ Заполнена верно (зелёный) — перезаполнять не нужно;
- ✖ Нужно перезаполнить (красный) — непроведённая, «Товары» расходятся; в колонке «Что не так» видно, какие позиции и сколько в документе / должно быть;
- ✖ Проведена, «Товары» расходятся — проведённый документ с расхождением (проверьте вручную);
- — нет данных — основание не «Приобретение товаров и услуг».
Тот же результат виден в колонке «Заполнение» на вкладке «Корректировки» и в печатной форме. Проверка только читает базу.

## Перезаполнить «Товары» последовательно
Ссылка «Перезаполнить Товары последовательно» на вкладке «Журнал выполнения»: по порядку цепочек берёт непроведённые корректировки со статусом «перезаполнить» (на вкладке журнала — только выделенные строки, если они выделены), выполняет «Заполнить корректируемые данные» и приводит количества строк (суммы пропорционально) к ожидаемым: поступление плюс расхождения всех корректировок цепочки до этой включительно. Не получилось привести (нет строки, несколько строк одной номенклатуры) — документ не записывается, причина в журнале. Документы только записываются, не проводятся; в пробном режиме не записываются. Проведённые не меняются.

## Вкладка «Магазины»
Магазин = склад возврата. Вкладка показывает по каждому магазину: сколько возвратов, из них можно удалять (100%), к перезаполнению, ждут корректировок, без совпадений, и сколько корректировок нужно перезаполнить. Отметьте магазин (или двойной щелчок по строке) — на вкладках «Возвраты и корректировки», «Корректировки» и «Журнал» останутся только документы этого магазина; «Выполнить» обрабатывает только показанные отмеченные возвраты, а «Перезаполнить Товары последовательно» — только корректировки этих магазинов. Ссылка «Показать все магазины» снимает отметки.

## Выбор корректировок для перезаполнения
В таблице цепочек первая колонка «Перезаполнить» — флажки. По умолчанию ничего не отмечено — галки ставит пользователь. Отметка ☐/☑ меняется двойным щелчком по ячейке; ссылки «Отметить все красные» и «Снять отметки» над таблицей; кнопка «Перезаполнить Товары последовательно» обрабатывает только отмеченные (плюс отбор по магазинам).

После перезаполнения строка цепочки получает статус «✔ перезаполнена» и голубую подсветку; в пробном режиме — «✔ (проба) будет перезаполнена…». Причина неудачи — в колонке «Сообщение». Новые статусы есть в поле «Показать».

Обработанные кнопкой «Перезаполнить» строки подсвечиваются голубым — их легко отличить от необработанных (красных) и верных (зелёных).

Над деревом «Возвраты и корректировки» есть поле «Склад» (выбор из магазинов подбора, кнопка очистки): оно синхронизировано с выбором на вкладке «Магазины».

Если в «Товарах» корректировки нет нужной строки, при перезаполнении она добавляется из «Товаров» поступления-основания (одноимённые реквизиты, суммы пропорционально количеству); в журнале стоит пометка «проверьте цену и НДС». Если в поступлении такой строки нет — добавить нужно вручную.

Над деревом «Возвраты и корректировки» ссылки «Отметить все» и «Снять все галки» — управляют колонкой «Обработать» у показанных возвратов.

## Вкладка «Магазины» — дерево
Дерево: склад (магазин) → приобретение → корректировки приобретения по порядку (К1, К2…) → возвраты поставщику, ссылающиеся на корректировку; возвраты без найденной корректировки — отдельным узлом в конце склада. Для каждого документа показаны дата, статус (проведён/не проведён), сумма и состояние («✔ верны», «✖ перезаполнить», «⚠ ждут» и т. д.); строки подсвечиваются. У склада — итоги по возвратам и корректировкам. Двойной щелчок по складу показывает его документы на первой вкладке, по документу — открывает его. Ссылки «Развернуть все» / «Свернуть все» / «Показать все магазины». У вкладки свой период («Период с / по») и ссылка «Сформировать за этот период» — дерево строится за выбранный период, остальные вкладки не меняются.

На вкладке «Магазины» над деревом поле «Склад» — отбор одного склада (список складов подбора, кнопка очистки).

Дерево вкладки «Магазины»: берутся возвраты за период (по умолчанию период шапки; на вкладке можно задать свой), а для каждого — поступление и все корректировки поступления по порядку без ограничения датами. Строится при первом открытии вкладки после «Подобрать» или по ссылке «Сформировать за этот период».
