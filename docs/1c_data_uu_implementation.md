# Дата УУ в PNL — инструкция по внедрению в 1С:КА

База разработки: `Srvr="10.10.10.200";Ref="kadata4";`
Рекомендуется делать в **расширении** конфигурации (чтобы не терять изменения при обновлении).
Имена полей ниже нужно сверить с вашей версией КА в конфигураторе (помечено «сверить»).

## 1.1 Реквизит «Дата УУ»

В расширении (или конфигурации) добавить реквизит табличной части:

| Документ | Табличная часть | Реквизит | Тип |
|---|---|---|---|
| ПриобретениеТоваровУслуг | Товары | ДатаУУ (синоним «Дата УУ») | Дата, состав «Дата», необязательный |
| ПриобретениеУслугПрочихАктивов | Расходы | ДатаУУ (синоним «Дата УУ») | Дата, состав «Дата», необязательный |

Затем:
1. Вывести колонку «Дата УУ» в табличной части формы документа (форма объекта, элемент таблицы).
2. Если документ вводится на основании/копированием — проверить, что колонка копируется.
3. Для робота: опубликовать новый реквизит в OData (состав стандартного интерфейса OData),
   тогда `rpa1c` сможет заполнять его (`ДатаУУ` в строках `Товары` / `Расходы`).

## 1.2 Правило получения фактических данных (произвольный запрос)

Бюджетирование и планирование → Настройки → Правила получения фактических данных → создать
правило с типом **«Произвольный запрос»** для затратных статей бюджета.

Текст запроса (сверить имена реквизитов суммы/подразделения/статьи):

```bsl
ВЫБРАТЬ
    ВЫБОР
        КОГДА Т.ДатаУУ <> ДАТАВРЕМЯ(1, 1, 1)
            ТОГДА НАЧАЛОПЕРИОДА(Т.ДатаУУ, ДЕНЬ)
        ИНАЧЕ НАЧАЛОПЕРИОДА(Т.Ссылка.Дата, ДЕНЬ)
    КОНЕЦ КАК Период,
    Т.Ссылка.Организация КАК Организация,
    Т.Ссылка.Подразделение КАК Подразделение,   // сверить
    Т.СтатьяРасходов КАК СтатьяБюджета,         // сверить: статья расходов / аналитика
    Т.СуммаСНДС - Т.СуммаНДС КАК Сумма          // сумма строки без НДС
ИЗ
    (ВЫБРАТЬ
        Т.Ссылка, Т.ДатаУУ, Т.СуммаСНДС, Т.СуммаНДС, Т.СтатьяРасходов
     ИЗ Документ.ПриобретениеТоваровУслуг.Товары КАК Т
     ГДЕ Т.Ссылка.Проведен
     ОБЪЕДИНИТЬ ВСЕ
     ВЫБРАТЬ
        Т.Ссылка, Т.ДатаУУ, Т.СуммаСНДС, Т.СуммаНДС, Т.СтатьяРасходов
     ИЗ Документ.ПриобретениеУслугПрочихАктивов.Расходы КАК Т
     ГДЕ Т.Ссылка.Проведен) КАК Т
ГДЕ
    ВЫБОР
        КОГДА Т.ДатаУУ <> ДАТАВРЕМЯ(1, 1, 1) ТОГДА Т.ДатаУУ
        ИНАЧЕ Т.Ссылка.Дата
    КОНЕЦ МЕЖДУ &НачалоПериода И &КонецПериода
```

Примечания:
- Подзапрос не может обращаться к `Т.Ссылка.Дата` после ОБЪЕДИНИТЬ ВСЕ без поля — при ошибке
  добавьте `Т.Ссылка.Дата КАК ДатаДокумента` в оба SELECT внутри подзапроса.
- Условие по дате в ГДЕ должно использовать те же параметры периода, что ожидает механизм
  правил (в КА — `&НачалоПериода`, `&КонецПериода`; проверить в справке правила типа «Произвольный запрос»).
- Состав выходных колонок должен совпадать с аналитиками показателя бюджета (проверить в настройке правила).

## 1.3 Замена действующих правил

1. Выгрузить список статей бюджета с типом «расход» и их текущие правила (для отката).
2. Для каждой расходной статьи: заменить текущее правило на новое (1.2), задать отбор по статье.
3. Пересчитать/перезаполнить фактические данные за нужный период.

## 1.4 Тестирование

- Документ с заполненной ДатаУУ в другом месяце → сумма попадает в PNL месяца ДатаУУ.
- Документ без ДатаУУ → месяц даты документа.
- Сумма = строка без НДС (сверить с суммой СНДС − НДС).
- Непроведённые документы не попадают.
- Сравнить итог PNL до/после по месяцам без ДатаУУ — совпадать должно.
